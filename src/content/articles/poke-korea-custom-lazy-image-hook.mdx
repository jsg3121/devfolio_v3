## 들어가며

포케코리아의 도감 리스트는 무한 스크롤로 되어 있습니다. 스크롤을 내릴 때마다 포켓몬 카드가 계속 추가되고, 카드마다 포켓몬 이미지가 하나씩 들어가요. 포켓몬이 1,000마리가 넘다 보니 이미지를 언제 불러오느냐에 따라 체감 속도가 꽤 달라졌습니다.

처음에는 브라우저가 기본으로 제공하는 `loading="lazy"`를 썼습니다. 그런데 이 방식으로는 모바일에서 효과를 보기 어렵겠다는 생각이 들었고, 결국 `IntersectionObserver`로 `useLazyImage`라는 훅을 직접 만들어 바꿨습니다. 이 글에서는 왜 그렇게 판단했는지, 훅은 어떻게 만들었는지, 실제로 어떻게 적용했는지를 정리해 보려고 합니다.

이미지 크기나 `fetchPriority` 이야기는 [포케코리아 웹 성능 최적화 3편](/articles/poke-korea-performance-3-responsive-images)에서 다뤘기 때문에, 이번에는 이미지를 **언제** 불러오는지에만 집중했습니다. 코드는 실제 프로젝트 코드에서 설명에 필요 없는 부분을 덜어 냈습니다.

## 1. 처음에는 loading="lazy"를 썼습니다

훅을 만들기 전 데스크톱 리스트 카드는 이렇게 되어 있었습니다. 앞쪽 20개 카드는 `fetchPriority="high"`로 먼저 불러오고, 나머지는 `loading="lazy"`를 붙여 브라우저에 맡기는 방식이었어요.

```tsx
// List.container.tsx
{
  pokemonList.map((pokemon, index) => (
    <PokemonCardComponent
      key={`pokemon-id-${pokemon.id}`}
      pokemonData={pokemon}
      setImagePriority={index < 20}
    />
  ));
}

// PokemonCard.component.tsx
<ImageComponent
  src={`${imageMode}/${pokemonData.number}.webp`}
  {...(setImagePriority ? { fetchPriority: 'high' } : { loading: 'lazy' })}
/>;
```

`loading="lazy"`는 속성 하나만 붙이면 끝이라 정말 편합니다. 화면 밖에 있는 이미지는 바로 받지 않고, 사용자가 스크롤해서 가까이 왔을 때 받아 옵니다.

## 2. 그런데 왜 바꿨을까

문제는 "얼마나 가까이 왔을 때" 받아 올지를 브라우저가 정한다는 점이었습니다. 브라우저는 사용자가 이미지에 도착하기 전에 로딩이 끝나 있도록 꽤 멀리서부터 미리 받아 오는데, 이 거리를 개발자가 바꿀 방법이 없습니다.

당시에 저는 이 거리가 기기와 상관없이 2000px 정도라고 알고 있었습니다. 그렇다면 모바일에서는 이야기가 달라집니다. 모바일 화면 높이가 보통 700~900px 정도이니, 2000px 앞에서부터 받아 온다는 건 아직 보이지도 않는 두세 화면 분량의 이미지를 미리 받는다는 뜻이거든요.

```text
+---------+
|         |  화면 (약 700~900px)
+---------+
|         |
|         |  미리 받는 구간 (약 2000px)
|         |  아직 안 보이지만 이미지를 받아 온다
|         |
+---------+
|         |  이후 구간
|         |  스크롤해서 가까워지면 받아 온다
```

화면이 작을수록 미리 받는 양이 상대적으로 많아지니까, 모바일에서는 지연 로딩의 효과가 크지 않을 거라고 판단했습니다. 그래서 "얼마나 미리 받을지"를 직접 정할 수 있는 방법이 필요했어요.

## 3. IntersectionObserver란?

훅에서 사용한 `IntersectionObserver`부터 간단히 소개하겠습니다.

`IntersectionObserver`는 **어떤 요소가 화면에 들어왔는지를 브라우저가 대신 알려주는 기능**입니다. 스크롤할 때마다 요소 위치를 직접 계산하지 않아도, 요소가 화면에 보이기 시작하거나 사라질 때 알려 줍니다.

```ts
const observer = new IntersectionObserver(callback, options);
observer.observe(element); // 이 요소를 지켜봐 줘
```

제가 쓴 옵션은 다음 장에서 코드와 함께 설명하고, 여기서는 쓰지 않은 것들만 짧게 정리해 둘게요.

| 항목                      | 설명                                                                                                        |
| ------------------------- | ----------------------------------------------------------------------------------------------------------- |
| `root`                    | 어디를 기준으로 볼지 정합니다. 생략하면 브라우저 화면이 기준이고, 스크롤되는 특정 영역을 지정할 수도 있어요 |
| `threshold` 배열          | `[0, 0.5, 1]`처럼 넘기면 0%, 50%, 100% 보일 때마다 알려 줍니다. 스크롤 진행률 표시 같은 곳에 쓰여요         |
| `entry.intersectionRatio` | 요소가 화면에 몇 % 보이는지를 0~1 사이 값으로 알려 줍니다                                                   |

[MDN — IntersectionObserver() constructor](https://developer.mozilla.org/en-US/docs/Web/API/IntersectionObserver/IntersectionObserver)

## 4. useLazyImage 훅 만들기

완성된 훅은 이렇습니다.

```ts
import { useEffect, useRef, useState } from 'react';

interface UseLazyImageOptions {
  rootMargin?: string;
  threshold?: number;
}

export const useLazyImage = (options: UseLazyImageOptions = {}) => {
  const [isVisible, setIsVisible] = useState<boolean>(false);
  const [isLoaded, setIsLoaded] = useState<boolean>(false);
  const imgRef = useRef<HTMLDivElement>(null);

  const { rootMargin = '200px', threshold = 0.1 } = options;

  useEffect(() => {
    const element = imgRef.current;
    if (!element) return;

    const observer = new IntersectionObserver(
      (entries) => {
        entries.forEach((entry) => {
          if (entry.isIntersecting && !isVisible) {
            setIsVisible(true);
            observer.unobserve(element); // 한번 보이면 observer 해제
          }
        });
      },
      {
        rootMargin,
        threshold,
      },
    );

    observer.observe(element);

    return () => {
      observer.disconnect();
    };
  }, [rootMargin, threshold, isVisible]);

  const handleImageLoad = () => {
    setIsLoaded(true);
  };

  const handleImageError = () => {
    setIsLoaded(false);
  };

  return {
    imgRef,
    isVisible,
    isLoaded,
    handleImageLoad,
    handleImageError,
  };
};
```

하나씩 살펴볼게요.

### rootMargin: 얼마나 미리 알려 줄지

이 훅에서 가장 중요한 옵션입니다. `rootMargin: '200px'`로 설정하면 화면 위아래를 200px씩 넓게 잡고 판단해요. 그래서 이미지가 실제로 화면에 보이기 200px 전에 "곧 보인다"는 신호를 받을 수 있습니다.

사용자가 스크롤해서 도착할 즈음에는 이미지가 이미 준비되어 있고, 그보다 멀리 있는 이미지는 아직 받지 않습니다. `loading="lazy"`와 달리 이 거리를 제가 직접 정할 수 있다는 점이 훅을 만든 가장 큰 이유였어요.

### threshold: 얼마나 들어와야 알려 줄지

`threshold: 0.1`은 요소가 10% 정도 걸쳤을 때 알려 달라는 뜻입니다. 위에서 화면을 200px 넓혀 두었으니, 실제로는 화면 200px 바깥에서 요소가 살짝 걸쳤을 때 이미지를 받기 시작합니다.

### isIntersecting: 들어왔는지만 보면 충분

브라우저가 알려 주는 정보(`entry`)에는 여러 값이 있지만, 이 훅은 "화면 근처에 들어왔나?"만 알면 됩니다. 그래서 `entry.isIntersecting` 하나만 확인합니다.

### unobserve와 disconnect: 한 번 받았으면 그만 지켜보기

이미지는 한 번 받아 오면 다시 받을 필요가 없습니다. 그래서 처음 들어온 순간 `unobserve`로 그 요소는 더 이상 지켜보지 않게 했고, 컴포넌트가 사라질 때는 `disconnect`로 깔끔하게 정리했습니다.

### 로딩 중에는 스켈레톤, 다 받으면 부드럽게

훅은 상태 두 개를 돌려줍니다.

| 상태        | 뜻                     | 화면에서는                 |
| ----------- | ---------------------- | -------------------------- |
| `isVisible` | 화면 근처에 들어왔는지 | 아직이면 스켈레톤을 보여줌 |
| `isLoaded`  | 이미지를 다 받았는지   | 다 받으면 서서히 나타남    |

화면 근처에 오기 전에는 `<img>` 태그를 아예 그리지 않고 스켈레톤만 보여 줍니다. 이미지를 그리기 시작한 뒤에도 다 받을 때까지는 투명하게 두었다가, 로딩이 끝나면 서서히 나타나게 했어요.

```tsx
const { imgRef, isVisible, isLoaded, handleImageLoad, handleImageError } = useLazyImage({
  rootMargin: '200px',
  threshold: 0.1,
});

<div ref={imgRef}>
  {isVisible ? (
    <Image
      src={imageSrc}
      onLoad={handleImageLoad}
      onError={handleImageError}
      style={{
        opacity: isLoaded ? 1 : 0,
        transition: 'opacity 0.3s ease-in-out',
      }}
    />
  ) : (
    <div className="bg-gray-300 opacity-30 animate-pulse rounded-lg" />
  )}
</div>;
```

## 5. 실제로 적용해 보기

### 곳마다 거리를 다르게

훅으로 만들어 두니 쓰는 곳마다 거리를 다르게 줄 수 있었습니다.

| 컴포넌트              | rootMargin | 이유                                               |
| --------------------- | ---------- | -------------------------------------------------- |
| 도감 리스트 카드      | `200px`    | 이미지가 크고 리스트가 길어서 여유 있게            |
| 챔피언스 티어 리스트  | `200px`    | 리스트 카드와 같은 구조라서                        |
| 헤더 검색 결과 리스트 | `50px`     | 32px짜리 작은 이미지에, 목록도 짧은 드롭다운이라서 |

`loading="lazy"`였다면 세 곳 모두 브라우저가 정한 같은 거리로 동작했을 거예요.

### 첫 화면 이미지는 바로 불러오기

나중에는 처음부터 화면에 보이는 이미지를 훅에서 빼냈습니다. 이미 화면 안에 있는 이미지까지 "들어왔다"는 신호를 기다리게 하면, 오히려 그만큼 늦게 보이기 때문입니다.

```tsx
{
  isHighPriority ? (
    // 첫 화면 이미지: 바로 우선순위 높게 받아 오기
    <Image src={imageSrc} fetchPriority="high" />
  ) : (
    // 나머지: 화면 근처에 오면 받아 오기
    <div ref={imgRef}>
      {isVisible ? <Image src={imageSrc} onLoad={handleImageLoad} /> : <Skeleton />}
    </div>
  );
}
```

이렇게 해서 첫 화면은 `fetchPriority="high"`로 최대한 빨리 보여 주고, 그 아래는 훅으로 필요한 만큼만 받아 오는 구조가 되었습니다.

## 6. 글을 쓰면서 다시 찾아본 것들

이번에 글을 정리하면서, 당시 판단이 맞았는지 공식 문서를 다시 찾아봤습니다.

### 2000px이 아니었다

제가 알고 있던 2000px은 정확한 숫자가 아니었습니다. Chrome은 이 거리를 **인터넷 속도에 따라** 다르게 잡고 있었어요.

| 인터넷 속도 | 미리 받기 시작하는 거리 |
| ----------- | ----------------------- |
| 4G          | 1250px                  |
| 3G 이하     | 2500px                  |

원래는 각각 3000px, 4000px이었는데 2020년 7월에 지금 값으로 줄었고, 현재 Chrome 소스 코드에도 같은 값이 들어 있습니다. 그리고 기기 종류는 기준에 들어가지 않았어요. [web.dev — Browser-level image lazy loading for the web](https://web.dev/articles/browser-level-image-lazy-loading)

숫자는 틀렸지만 "기기와 상관없이 브라우저가 정한 거리부터 미리 받고, 개발자는 이 거리를 바꿀 수 없다"는 판단 자체는 맞았던 셈입니다.

### loading="lazy"도 결국 IntersectionObserver였다

재밌는 사실도 하나 알게 됐습니다. Chrome 소스 코드를 보니 `loading="lazy"`도 내부에서는 `IntersectionObserver`로 동작하고 있었어요. 인터넷 속도에 맞는 거리를 고른 다음, 그 값으로 옵저버를 만드는 식입니다. [Chromium — lazy_load_media_observer.cc](https://chromium.googlesource.com/chromium/src/+/main/third_party/blink/renderer/core/html/media/lazy_load_media_observer.cc)

결국 브라우저 기본 기능과 제가 만든 훅은 같은 원리였고, 차이는 "얼마나 미리 받을지를 누가 정하느냐" 하나였습니다.

## 마치며

`loading="lazy"`는 정말 간편하지만, 이미지를 얼마나 미리 받을지는 브라우저가 정하고 개발자는 손댈 수 없습니다. 화면이 작은 모바일에서는 이 거리가 상대적으로 크게 느껴지기 때문에, 직접 정할 수 있는 방법이 필요했습니다.

`IntersectionObserver`의 `rootMargin`을 쓰면 이 거리를 직접 정할 수 있고, 훅으로 만들어 두면 쓰는 곳마다 다르게 맞출 수도 있습니다. 여기에 첫 화면 이미지는 바로 불러오고 나머지만 지연 로딩하도록 나누면서, 이미지를 불러오는 시점을 화면 위치에 맞게 정리할 수 있었습니다.
