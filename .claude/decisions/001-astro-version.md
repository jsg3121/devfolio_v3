# ADR-001: Astro 버전 선택 (v5 vs v6)

## 상태

승인됨 (2025-03-19)

## 배경

프로젝트 초기 셋업 시점에 Astro의 최신 메이저 버전인 v6(2025-03-10 릴리스)이 공개된 상태였다. 기존 안정 버전인 v5와 비교하여 어떤 버전을 채택할지 결정이 필요했다.

이 프로젝트는 경력 아카이브형 포트폴리오 사이트로, 다음과 같은 특성을 갖는다:

- **정적 사이트(SSG)** 기반으로 빌드 후 CDN 배포
- 장기 운영을 전제로 하며, 콘텐츠 추가/수정이 주된 유지보수 작업
- Vercel 또는 Cloudflare Pages에 배포 예정
- 개발 환경의 Node.js 버전은 20 LTS

프레임워크 버전은 프로젝트 전체 의존성과 개발 워크플로에 영향을 미치므로, 초기에 신중하게 결정할 필요가 있었다.

## 논의 내용

### Astro 6의 주요 변경점

| 영역 | 변경 내용 | 프로젝트에 미치는 영향 |
|------|-----------|----------------------|
| **런타임** | Node.js 22 이상 필수 (v5는 Node 20 지원) | 현재 개발 환경(Node 20 LTS)에서 즉시 사용 불가. 배포 환경도 Node 22 지원 여부를 별도 확인해야 함 |
| **빌드** | Vite 6 기반 빌드 시스템 | 빌드 성능 개선이 기대되나, Vite 6 자체도 비교적 최신이라 플러그인 호환성 리스크 존재 |
| **콘텐츠 API** | Content Layer가 유일한 콘텐츠 API. 기존 `getCollection()` 방식이 변경되고, `glob()` loader가 기본 | 이 프로젝트는 Content Collections를 핵심으로 사용하므로 API 변경의 영향이 큼. 다만 v5에서도 `glob()` loader를 opt-in으로 사용할 수 있어 호환 코드 작성 가능 |
| **반응성** | `Astro.state`, 서버 액션 등 반응성 시스템 도입 | 이 프로젝트는 정적 사이트(SSG)이므로 서버 사이드 반응성 기능은 사용하지 않을 가능성이 높음 |
| **Tailwind** | `@astrojs/tailwind` 공식 제거 → `@tailwindcss/vite` 플러그인으로 전환 | v5에서도 `@tailwindcss/vite` 방식을 사용할 수 있으므로 호환 코드 작성 가능 |
| **SVG** | 실험적 SVG 컴포넌트 API | 아이콘 처리에 유용할 수 있으나, 실험적 기능이므로 의존하기 어려움 |
| **Breaking Changes** | 설정 파일 위치 변경, 일부 API 시그니처 변경 등 | 릴리스 직후라 전체 Breaking Changes 목록의 실제 영향을 파악하기 어려움 |

### Astro 5의 장점

- **Node.js 20 LTS 지원**: 현재 개발 환경과 배포 환경(Vercel, Cloudflare Pages) 모두에서 안정적으로 동작한다. Node 20은 2026-04까지 LTS 유지보수 기간이므로 당분간 안전하다.
- **안정적인 에코시스템**: `@astrojs/mdx`, `@astrojs/sitemap` 등 이 프로젝트에서 사용할 공식 인테그레이션이 v5에서 충분히 검증되어 있다. 서드파티 플러그인과의 호환성도 확인된 상태다.
- **v6 호환 코드 작성 가능**: Content Collections에서 `glob()` loader를 사용하고, 설정 파일을 `src/content.config.ts`에 배치하면 v6과 동일한 패턴을 유지할 수 있다. Tailwind도 `@tailwindcss/vite` 방식을 v5에서 그대로 사용 가능하다.
- **충분한 문서와 커뮤니티**: 공식 문서, 튜토리얼, Stack Overflow 답변 등이 v5 기준으로 풍부하게 존재한다. 문제 발생 시 해결 방법을 찾기 쉽다.

### Astro 6의 리스크

- **릴리스 직후 불안정성**: v6가 공개된 지 약 9일(2025-03-10 → 2025-03-19)밖에 되지 않아, 초기 버그나 예상치 못한 이슈가 발생할 가능성이 높다. 특히 이 프로젝트처럼 MDX + Content Collections + Tailwind를 함께 사용하는 조합에서의 호환성이 충분히 검증되지 않았다.
- **서드파티 인테그레이션 미검증**: `eslint-plugin-astro`, `prettier-plugin-astro` 등 개발 도구 생태계가 v6을 아직 공식 지원하지 않을 수 있다. 이 경우 개발 경험(DX)이 저하된다.
- **배포 환경 제약**: Node 22 필수 요구사항이 Vercel/Cloudflare Pages에서 문제없이 동작하는지 별도 확인이 필요하다. 특히 Cloudflare Workers의 Node.js 호환성 레이어는 제한이 있을 수 있다.
- **학습 비용**: Astro 6의 새로운 API나 변경된 패턴에 대한 공식 마이그레이션 가이드가 아직 충분하지 않아, 문제 발생 시 해결에 시간이 더 소요될 수 있다.

### 프로젝트 요구사항과의 매칭

이 프로젝트의 핵심 요구사항을 기준으로 두 버전을 비교하면:

| 요구사항 | Astro 5 | Astro 6 |
|---------|---------|---------|
| Content Collections (MDX) | 안정적 지원 | 지원하나 API 변경됨 |
| Tailwind CSS v4 | `@tailwindcss/vite`로 사용 가능 | 동일 |
| SSG 정적 빌드 | 기본 모드 | 기본 모드 |
| Vercel/CF Pages 배포 | Node 20 호환, 검증됨 | Node 22 필요, 미검증 |
| 장기 운영 안정성 | 높음 | 낮음 (초기 릴리스) |

## 결정

**Astro 5를 사용한다.**

단, Astro 6 마이그레이션을 용이하게 하기 위해 아래 3가지 호환 전략을 적용한다:

1. **Content Collections는 `glob()` loader 사용**: v5의 기존 방식 대신 `glob()` loader를 사용하면 v6에서 그대로 동작한다. 이는 v5에서 opt-in으로 제공되는 기능이다.
2. **설정 파일은 `src/content.config.ts` 위치**: v5에서는 `src/content/config.ts`가 기본이지만, `src/content.config.ts` 위치도 지원한다. v6에서는 후자가 권장 위치이므로 미리 맞춰둔다.
3. **Tailwind는 `@tailwindcss/vite` 플러그인 사용**: `@astrojs/tailwind` 인테그레이션 대신 Vite 플러그인 방식을 사용한다. v6에서 `@astrojs/tailwind`가 제거되었으므로 이 방식이 미래 호환적이다.

## 근거

- **안정성 우선**: 포트폴리오는 장기 운영 프로젝트이므로, 릴리스 직후의 최신 버전보다 충분히 검증된 버전이 적합하다. 초기 셋업 단계에서 프레임워크 버그로 시간을 소비하는 것은 비효율적이다.
- **환경 호환성**: 현재 Node 20 LTS 환경에서 개발하고 있으며, 배포 환경도 Node 20 기준으로 설정되어 있다. 불필요한 런타임 업그레이드를 피한다.
- **마이그레이션 비용 최소화**: 위 3가지 호환 전략을 적용하면, 향후 v6으로 업그레이드할 때 설정 파일 변경과 일부 API 조정만으로 마이그레이션이 가능하다. 핵심 코드의 대규모 수정 없이 전환할 수 있다.
- **실용적 판단**: v6의 새 기능(반응성, 서버 액션 등)은 이 프로젝트(SSG 정적 사이트)에서 활용할 가능성이 낮다. 새 기능의 이점이 적고 리스크가 큰 상황이다.
